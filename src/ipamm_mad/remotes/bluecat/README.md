# BlueCat IPAM Driver

This directory contains the OpenNebula IPAM driver action scripts for a BlueCat-backed IPAM integration.

The driver currently supports validated mock-mode behavior for OpenNebula lifecycle testing and provisional REST calls for BlueCat Address Manager (BAM). The non-mock BAM API paths are experimental and have not yet been validated against a real BAM instance. Do not treat this driver as full BlueCat production support without site-specific BAM validation.

## Driver Architecture

OpenNebula invokes one script per IPAM action and passes the request ID as the first argument. The action payload is read from standard input as the base64-encoded XML generated by OpenNebula.

Each script:

1. Sources OpenNebula shell helpers from `$ONE_LOCATION/lib/sh/scripts_common.sh` or `/usr/lib/one/sh/scripts_common.sh`.
2. Parses the XML payload with `src/ipamm_mad/remotes/datastore/xpath.rb`.
3. Sources `common.sh` for shared BlueCat logging, config loading, and error helpers.
4. Loads `/etc/one/bluecat_ipam.conf` unless `BLUECAT_CONFIG` points to another file.
5. Runs either mock behavior or the provisional BlueCat API path.

Logs are written to `/tmp/bluecat-ipam.log` by default. Set `BLUECAT_LOG` before invoking a script to write somewhere else.

## Supported IPAM Actions

| Script | OpenNebula action | Validated mock-mode behavior | Provisional non-mock BAM API behavior |
| --- | --- | --- | --- |
| `register_address_range` | Register an address range | Returns an OpenNebula `AR = [...]` definition using the request data. Validated through VNET create lifecycle testing. | Attempts to create a BlueCat network under `BLUECAT_PARENT_BLOCK_ID`/`BLUECAT_BLOCK_ID`, or validate an existing `BLUECAT_NETWORK_ID`. Endpoint and payload behavior are not yet validated against a real BAM instance. |
| `unregister_address_range` | Unregister an address range | Exits successfully after logging. Validated through VNET delete lifecycle testing. | No-op by default. If `BLUECAT_UNREGISTER_ACTION=delete`, attempts to delete the backing BlueCat network. Not yet validated against a real BAM instance. |
| `get_address` | Allocate the next free address | Returns the AR base IP in `ADDRESS = [...]`. Validated through dynamic VM IP lifecycle testing. | Attempts to ask BlueCat for an address and emits `ADDRESS = [...]`. Not yet validated against a real BAM instance. |
| `allocate_address` | Mark a requested address as used | Accepts the requested address and exits successfully. Validated through fixed VM IP lifecycle testing. | Attempts to create/reserve the requested address in BlueCat. Not yet validated against a real BAM instance. |
| `free_address` | Release an address | Exits successfully after logging. Validated through VM terminate lifecycle testing. | Looks up the address and deletes it if found. Not yet validated against a real BAM instance. |

## Validation Status

- VNET create -> `register_address_range` validated in mock mode.
- Dynamic VM IP -> `get_address` validated in mock mode.
- Fixed VM IP -> `allocate_address` validated in mock mode.
- VM terminate -> `free_address` validated in mock mode.
- VNET delete -> `unregister_address_range` validated in mock mode.

Non-mock BlueCat BAM API behavior is provisional/experimental and is not yet validated against a real BAM instance.

## Required Config

Create `/etc/one/bluecat_ipam.conf` on the OpenNebula front-end. For local testing, set `BLUECAT_CONFIG` to an alternate file.

Minimum mock config:

```bash
BLUECAT_MOCK=yes
BLUECAT_NETWORK_ID=mock-network
```

Non-mock config:

```bash
BLUECAT_MOCK=no
BLUECAT_URL=https://bluecat.example.com
BLUECAT_USER=api-user
BLUECAT_PASS=api-password

# Existing network used by address operations, or returned by AR registration.
BLUECAT_NETWORK_ID=12345

# Optional parent block used by register_address_range when creating networks.
BLUECAT_PARENT_BLOCK_ID=67890
# BLUECAT_BLOCK_ID is also accepted as a fallback for BLUECAT_PARENT_BLOCK_ID.

# Optional name used when creating a BlueCat network.
BLUECAT_NETWORK_NAME=opennebula-network

# unregister_address_range keeps BlueCat networks unless this is set to delete.
BLUECAT_UNREGISTER_ACTION=keep
```

Non-mock mode requires `curl`. Actions that parse BlueCat JSON responses also require `jq`.

## Before Enabling Non-Mock Mode

Before setting `BLUECAT_MOCK=no`, confirm all of the following:

- A BlueCat BAM test environment is available.
- API credentials are available and scoped appropriately for testing.
- A dedicated test block/network is available for OpenNebula validation.
- The exact BAM API version and endpoint behavior are confirmed.
- Customer/site policy is clear for network creation/deletion and address release.

## Mock Mode

Mock mode is enabled with:

```bash
BLUECAT_MOCK=yes
```

Mock mode does not call BlueCat. It keeps the OpenNebula action flow usable for local validation and has been validated with OpenNebula lifecycle testing:

- `register_address_range` echoes an `AR = [...]` response using the request data.
- `get_address` returns `ADDRESS = [ IP = "$AR_IP", SIZE = "$ADDR_SIZE" ]`.
- `allocate_address`, `free_address`, and `unregister_address_range` exit successfully after logging.

## Testing Workflow

Validate shell syntax after edits:

```bash
bash -n common.sh register_address_range unregister_address_range get_address allocate_address free_address
```

Run mock-mode action tests with a temporary config:

```bash
export BLUECAT_CONFIG=/tmp/bluecat_ipam.conf
export BLUECAT_LOG=/tmp/bluecat-ipam-test.log

cat > "$BLUECAT_CONFIG" <<'EOF'
BLUECAT_MOCK=yes
BLUECAT_NETWORK_ID=mock-network
EOF
```

Then invoke individual scripts the same way OpenNebula does: pass a request ID as `$1` and provide the base64 XML payload on stdin. Check stdout for the OpenNebula response contract and inspect `$BLUECAT_LOG` for parsed request details.

For non-mock testing, use a dedicated BlueCat test configuration, test block, and disposable networks/addresses. Confirm behavior in BlueCat after each action. These paths are provisional until validated against the target BAM instance and version.

## Current Limitations

- The non-mock API calls are provisional and have not been validated as a complete BAM integration.
- Authentication is basic-auth style only; no session lifecycle, token refresh, or certificate policy handling is implemented.
- `get_address` and `allocate_address` do not fully support multi-address reservations beyond preserving `SIZE` in the OpenNebula response/logs.
- BlueCat response parsing accepts several likely JSON shapes, but this needs to be aligned with the exact BAM API version in use.
- Error responses are intentionally simple: scripts log details and return `-1` for OpenNebula-facing failures.
- There is no persistent reconciliation between OpenNebula allocations and BlueCat metadata yet.

## Future BAM API Integration Work

- Replace provisional endpoint paths and payloads with BAM-version-specific client calls.
- Add robust network discovery and duplicate-network handling for `register_address_range`.
- Add first-fit/next-fit allocation policy support for `get_address`.
- Support contiguous multi-address allocation and release.
- Store OpenNebula VM, NIC, VNet, and AR metadata on BlueCat objects where site policy allows it.
- Add idempotency for retries and partial failures.
- Add integration tests against a BlueCat test environment or a contract-test fixture with captured BAM responses.
